**`@cached` no longer gives calls that differ only in a secret one key.**
pydantic writes a secret as `"**********"`, so
`load(Creds(token=SecretStr("a")))` and the same call with token `"b"` shared
an entry, and in a multi-tenant app one tenant could get another's result. An
argument that holds a `SecretStr`, `SecretBytes` or `Secret[...]`, at any
depth and in dict keys too, now raises `CacheXError` and asks for `key=`.
`CacheManager.set()`, which already refused values holding `SecretStr` or
`SecretBytes`, now also refuses `Secret[...]` and secrets used as dict keys.
