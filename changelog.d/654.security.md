**`@cached` now refuses an argument that holds a pydantic secret, instead of
keying every secret the same.** pydantic writes a secret as `"**********"`, so
`load(Creds(token=SecretStr("a")))` and the same call with token `"b"` shared
an entry, and in a multi-tenant app one tenant could get another's result. An
argument whose JSON form holds a `SecretStr`, `SecretBytes` or `Secret[...]`
mask, at any depth and in dict keys too, now raises `CacheXError` and asks for
`key=`; a secret that a field serializer writes out in full is keyed by its
value, as before. `CacheManager.set()`, which already refused values holding
`SecretStr` or `SecretBytes`, now also refuses `Secret[...]` and secrets used
as dict keys.
